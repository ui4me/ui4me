# Core 0.6 — Complete public document and HTML interface

**Purpose:** Expose already internal document functionality and finish forms/events.

**Work items:** 10 (release scope; not claims of current absence).

## Release gate

All applicable work items must have recorded source identity, public language-neutral contract where needed, targeted tests, installed Python/PowerShell behavior and OS-native qualification for platform-bound features. No invented test passes. Legitimately unavailable OS capabilities must return explicit unsupported/denied; they are not silently simulated. Block on P0/P1 correctness, memory/callback safety and native installed failures; record small cosmetic/performance differences without blocking.

## Definition of done

- One clean commit or a few coherent feature-slice commits, with recorded git SHA.
- No blanket source copy or reimplementation of existing internal code.
- New public operations exposed through C ABI/typed protocol and both Python/PowerShell where relevant; no new JS/browser runtime.
- Only affected tests during work; cross-platform installed integration on milestone candidate.
- Evidence records pass/fail/not_run/blocked; maintain a concise ledger.
- Release and registry publication require separate authorization.
